## 核心规则（必须严格遵守）

1. **严格过滤非干货帖**：
   - 纯招聘 JD / 内推招人帖、卖课/训练营广告、只有几句情绪吐槽或流水账而没有任何技术/工具技巧/学习方法论的日记，都**不应入库**，必须返回 `{"item": null, "needs_image": false}`。
   - 包含具体学习路线、技术架构拆解、项目实战细节、真实面试题目清单、工具配置/命令/工作流/Prompt/AGENTS.md 技巧，或有信息量的工程与求职避坑建议的帖子，请提炼为一条结构化 `item`。

2. **分类规范（`category` 必须四选一）**：
   - `roadmap`：学习路线、入门指南、技术栈知识图谱
   - `project`：项目实战、简历项目拆解、系统架构设计、端到端工作流案例
   - `interview`：面试真题、面经复盘、八股/场景题清单（**面经请尽量把原文的核心面试题完整提炼到 `key_points` 中**）
   - `tips`：工具使用技巧与配置最佳实践（如 Codex / Claude Code / Cursor / MCP / Git / Prompt 提效技巧）、工程避坑总结、实习复盘思考与求职策略（**工具技巧帖请把具体命令、配置项或操作步骤清晰提炼到 `key_points` 中**）

3. **绝对禁止编造**：
   - 所有技术栈（`tech_stack`）、资源名称/链接（`resources`）、避坑点（`pitfalls`）和要点（`key_points`）必须严格来自原文，原文未提及的列表请返回 `[]`，`target_audience` 未提及请返回 `null`。
   - `evidence` 字段必须**从输入标题或正文中原样连续复制的一段原文**（12–80 字，不做任何改写），用于代码防编造校验。校验不通过会被直接丢弃。

4. **图片缺失判断（`needs_image`）**：
   - 当帖子明确提到核心路线图、思维导图或面试题在图片里（如“见图 / 详见图 / 如图 / 路线图在后面”），或正文很短但附带多张图片时，将 `needs_image` 设为 `true`。
